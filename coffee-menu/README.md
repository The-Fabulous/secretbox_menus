# Secretbox — меню кофеен

Сайт-меню с заказом. Все данные лежат в JSON — код сайта менять не нужно, чтобы добавить кофейню, позицию или поменять цену.

## Запуск

Дважды кликнуть `start.cmd` (нужен Python) — откроется http://localhost:8000.
Открыть `index.html` напрямую нельзя: браузер не даёт странице, открытой как файл, читать JSON.

## Где какие данные

| Файл | Что внутри | Будущая таблица в БД |
|---|---|---|
| `data/cafes.json` | бренд Secretbox и список кофеен: название, логотип, адрес, валюта, файл меню | `cafes` |
| `cafes/<id>.json` | разделы и позиции меню кофейни (шаблон — `master_coffe.json`) | `categories`, `items`, `variants` |
| `data/categories.json` | общие настройки разделов: цвет карточек, что к чему рекомендовать, время по умолчанию | `category_styles` |
| `data/tags.json` | метки позиций: Хит, Новинка, Острое, Веган… (по ним работает фильтр) | `tags` |
| `qr.html` | страница печати QR-кодов для столов | — |
| `data/menu.schema.json` | описание формата меню (подсказки и проверка в VS Code) | — |
| `pictures/logos/` | логотипы | — |
| `pictures/items/<id кофейни>/` | фото позиций | — |

Кофейня открывается по адресу `?cafe=<id>`. Без параметра — начальный экран Secretbox со списком кофеен.
`?cafe=<id>&table=5` — меню для стола 5: в шапке «Стол 5», в заказе сразу «В зале · стол 5».

## Правило `null`

Если у позиции чего-то нет (описание, состав, объём, КБЖУ, время приготовления) — пишите `null`. Блок под это значение на сайте не создаётся.

## Фото позиций

У каждой позиции уже прописан путь в `image_url`, например:

```
pictures/items/master_coffe/item_latte.jpg
```

Достаточно положить файл с таким именем в эту папку — фото появится. Пока файла нет, показывается иконка раздела.

## Формат меню (`cafes/<id>.json`)

```json
{
  "categories": [
    { "id": "coffee", "name": "Кофе", "icon": "☕", "order": 1 }
  ],
  "items": [
    {
      "id": "item_latte",
      "category_id": "coffee",
      "name": "Латте",
      "image_url": "pictures/items/master_coffe/item_latte.jpg",
      "description": null,
      "ingredients": null,
      "prep_time_min": 5,
      "is_special": false,
      "variants": [
        {
          "variant_id": "var_latte_std",
          "measure": "400 мл",
          "price": 1190,
          "nutrition": null
        }
      ]
    }
  ]
}
```

- `category_id` — один из разделов файла. Цвет и рекомендации берутся из `data/categories.json` по тому же id (`coffee`, `tea`, `cocoa`, `cold_drinks`, `pastry`, `desserts`, `breakfast`, `snacks`, `hot_meals`, `combo`).
- `is_special: true` — позиция попадает в блок «Сегодня в меню».
- `variants` — если вариантов несколько (например, 250 / 350 / 450 мл), на сайте появляется выбор, у каждого своя цена и КБЖУ.
- `id` позиции не меняйте после запуска — по нему хранятся заказы гостей.

## Добавки к напиткам

Группы добавок описываются в файле меню, в `modifier_groups`:

```json
"modifier_groups": [
  {
    "id": "milk", "name": "Молоко", "type": "single", "applies_to": ["coffee", "cocoa"],
    "options": [
      { "id": "regular", "name": "Обычное", "price": 0, "default": true },
      { "id": "oat", "name": "Овсяное", "price": 300 }
    ]
  },
  {
    "id": "syrup", "name": "Сироп", "type": "multi", "max": 2, "applies_to": ["coffee"],
    "options": [{ "id": "vanilla", "name": "Ванильный", "price": 200 }]
  }
]
```

- `type: "single"` — выбирается один вариант (молоко), `"multi"` — несколько (сиропы, не больше `max`).
- `applies_to` — к каким разделам группа применяется.
- Чтобы у позиции был свой набор, добавьте ей `"modifier_group_ids": ["extra"]`. Пустой список `[]` — у позиции нет добавок.
- В заказе «капучино на овсяном» и «капучино» — разные строки, доплата прибавляется к цене.

## Языки (RU / KZ / EN)

Переключатель языка — в шапке справа. Тексты интерфейса — в `i18n.js`. Названия, описания и состав позиций, разделов и добавок переводятся в JSON меню полем `i18n`:

```json
{
  "id": "item_latte",
  "name": "Латте",
  "i18n": {
    "kz": { "name": "Латте" },
    "en": { "name": "Latte", "description": "...", "ingredients": ["Espresso", "Milk"] }
  }
}
```

Нет перевода — показывается русский текст. Поиск по меню ищет и на выбранном языке, и по-русски.

## Метки и фильтры

У позиции в файле меню: `"tags": ["hit", "vegan"]`. Список меток (название, эмодзи, цвет, переводы) — в `data/tags.json`. Первая метка показывается на карточке, все — в окне позиции. Кнопка фильтров в ленте разделов: по меткам (у позиции должны быть все выбранные) и по цене «до».

## QR-коды для столов

Откройте `qr.html` (через `start.cmd` или на сайте), выберите кофейню и номера столов, укажите адрес сайта в интернете и нажмите «Печать» — получатся карточки с логотипом, QR-кодом и номером стола. С адресом `localhost` коды с телефона не откроются — страница об этом предупредит.

## Профиль гостя

Аватар справа вверху: имя для заказа, избранное (♡ на карточке) и история заказов с кнопкой «Повторить». Хранится только в браузере гостя, отдельно для каждой кофейни. Настоящей оплаты пока нет: «Оплатить» сохраняет заказ в историю и очищает корзину.

## Оформление

- Фирменный цвет кофейни — `"theme": { "accent": "#0b6f7a" }` в `data/cafes.json`. Кнопки, выбранные варианты и метки окрашиваются в него; без поля — цвет по умолчанию.
- Тёмная тема включается сама, если она включена на телефоне или компьютере гостя.

## Как добавить кофейню

1. Создать `cafes/new_cafe.json` (можно пустым — будет «Меню пока пустое»).
2. Положить логотип в `pictures/logos/`.
3. Добавить кофейню в `data/cafes.json`:
   ```json
   {
     "id": "new_cafe",
     "name": "New Cafe",
     "file": "cafes/new_cafe.json",
     "logo": "pictures/logos/logo_new.png",
     "address": null,
     "city": null,
     "hours": null,
     "currency": "KZT",
     "theme": { "accent": "#0b6f7a" }
   }
   ```

## Переход на базу данных

Весь доступ к данным — в `api.js` (`getCafes`, `getMenu`, `getStyles`). Чтобы перейти на БД, нужен сервер, который отдаёт JSON того же формата, и замена адресов в `ENDPOINTS`:

```js
cafes:  () => '/api/cafes',
menu:   cafe => `/api/cafes/${cafe.id}/menu`,
styles: () => '/api/category-styles',
```

`app.js` работает только с уже нормализованными данными и при этом не меняется.
