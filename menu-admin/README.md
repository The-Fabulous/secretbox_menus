# Панель загрузки новых заведений

Страница `coffee-menu/admin.html`: общий вход сотрудников → выбор папки с `cafe.json` и скринами → проверка → «Создать вкладку» → этапы обработки → ссылка на меню.

Сайт остаётся на GitHub Pages. Worker принимает загрузку, записывает **новую** папку только в `venues/<id>/` одним коммитом и показывает состояние workflow `parse-menu.yml`. Распознавание выполняет существующий Python-драйвер в GitHub Actions. Проценты показываются только для передачи файлов; распознавание и публикация — по реальным этапам Actions.

**Код подготовлен, но сервер автоматически не развёрнут.** Пока `admin_api_url` равен `null`, страница показывает, что требуется подключение. Секретов в исходниках нет.

## Однократное подключение администратором

1. В GitHub создайте fine-grained personal access token **только для `The-Fabulous/secretbox_menus`**:
   - Contents: Read and write — загрузка новых исходников;
   - Actions: Read and write — чтение статуса и повтор неуспешного запуска;
   - Metadata: Read — автоматически.
   Если организация требует одобрения токенов, дождитесь его. Права на другие репозитории не нужны. Используйте PAT, а не `GITHUB_TOKEN` из Actions: push должен запускать обработку.
2. В среде с Node.js установите/запустите официальный Wrangler и войдите в свой Cloudflare-аккаунт. Из папки `menu-admin`:
   ```powershell
   npx wrangler login
   npx wrangler secret put ADMIN_PASSWORD
   npx wrangler secret put GITHUB_TOKEN
   npx wrangler deploy
   ```
   `ADMIN_PASSWORD` — случайный общий пароль команды, не менее 16 символов. `GITHUB_TOKEN` — токен из первого шага. Команды запрашивают значения интерактивно. Не вписывайте секреты в `wrangler.toml`, `config.json`, исходники или чат.
3. В `coffee-menu/data/config.json` задайте адрес из результата deploy:
   ```json
   "admin_api_url": "https://secretbox-menu-admin.ВАШ_АККАУНТ.workers.dev"
   ```
4. Отправьте изменение сайта в GitHub. Откройте `admin.html`, войдите и загрузите тестовую папку **нового** заведения. Проверьте создание папки в `venues/`, задачу «Меню из фото» и готовую вкладку.

В репозитории должен быть секрет `OPENAI_API_KEY` для Gemma. В **Settings → Pages** источник — GitHub Actions. Панель не получает ключ Gemma.

`wrangler.toml` уже содержит репозиторий и разрешённые адреса сайта. Если сайт переезжает, измените `ALLOWED_ORIGINS`. Namespace ID ограничителей `10031`/`10032` должны быть свободны в вашем Cloudflare-аккаунте; при совпадении с другим Worker выберите другие.

## Работа сотрудников

- Вход по общему паролю. Сессия действует до 8 часов и хранится только в памяти страницы. Обновление страницы требует повторного входа. Выход прекращает доступ в этой странице, но не отменяет уже запущенное распознавание.
- Последняя заявка (только id и SHA, без пароля и токена) сохраняется в браузере. После повторного входа статус восстанавливается.
- Выбирается папка одного заведения, все файлы непосредственно внутри. Имя вкладки — строчная латиница, цифры и `_`, начинается с буквы.
- Обязателен `cafe.json` с `name`. Опциональные `pickup` и `delivery` работают как прежде. Логотип — файл в той же папке, указанный в `logo`.
- До 24 файлов, до 8 МБ на файл, до 20 МБ на папку. Только JSON-конфиг и JPG/JPEG/PNG/WebP/BMP. Скрытые служебные файлы `.DS_Store`, `.gitkeep`, `Thumbs.db` пропускаются интерфейсом.
- Папки с существующим id, включая ручные меню, не заменяются. Обновлять старые заведения пока следует привычным способом через репозиторий.
- Исходники попадают в репозиторий: при публичном репозитории они будут публичны.
- При сетевом сбое повторите ту же загрузку в открытой странице. Номер заявки позволяет найти уже принятый коммит без дубля. После перезагрузки при неизвестном результате сначала проверьте Actions и папку: существующий id заблокирует повторную запись.
- Кнопка «Открыть новую вкладку» появляется только после успешного deploy. Отсутствие новой публикации, ошибка и отмена показываются отдельно. После ошибки/отмены есть повтор обработки и ссылка на журнал GitHub (для приватного репозитория сотруднику нужен доступ к журналу).
- GitHub может отменять промежуточные ожидающие задачи при нескольких быстрых загрузках в общую concurrency-группу. Панель отобразит отмену; её можно повторить после завершения текущей задачи.

## Доступ и границы

Все операции API проверяют сессию на сервере. Общий пароль позволяет любому знающему его сотруднику создавать новые вкладки и повторять обработку. Персональных аккаунтов и отдельного аудита сотрудников пока нет. Смена `ADMIN_PASSWORD` отзывает ранее выданные сессии.

Попытки входа ограничены пятью в минуту на IP, загрузки — пятью в минуту на Worker-location. Это защита от частых запросов, а не глобальный строгий счётчик. Токен GitHub хранится только в секретах Worker. Серверные исключения и ответы с секретами не возвращаются в браузер. Назначение записи задаётся сервером; клиент не может выбрать другой репозиторий, ветку или путь вне `venues/<id>/`. Обновление ветки использует `force: false`.

Сам fine-grained token имеет Contents write на репозиторий целиком: более узкого ограничения по папке у него нет. Ограничение папкой выполняется кодом сервера. Не используйте этот токен в других приложениях.

## Проверка без внешних записей

```powershell
node --test menu-admin/tests/worker.test.mjs
node menu-admin/tests/preview.mjs --demo
```

Второй запуск открывает локальный сервер `http://127.0.0.1:8767/admin.html`, пароль **`demo-password-12345`**. Это только тест: GitHub и Gemma заменены ответами в памяти, файлы в репозиторий не отправляются, на странице показана явная пометка. Этот сервер не предназначен для публикации или настоящих секретов.
